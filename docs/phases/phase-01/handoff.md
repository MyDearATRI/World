核心输入与输出：

- `ontology/math_outline.md`：只有标题的三卷树。
- `ontology/math_registry.json`：稳定ID、规范中英文标题、别名、多父归属、来源和官方分类映射。
- `ontology/sources.json`：已读取的来源位置、短摘要、来源组和日期精度。

- `ontology/benchmarks/`：官方分类提取快照、固定抽样、研究包、审阅记录及有限可复跑脚本。
- `scripts/validate-ontology.mjs` 与 `scripts/ontology.test.mjs`：独立数据校验和17项边界测试。

从网站目录复跑：

```powershell
node scripts/validate-ontology.mjs
node --test scripts/ontology.test.mjs
node ontology/benchmarks/run-acceptance.mjs
```

最后一个命令保存新的实际日志和哈希；它不会下载论文、运行导出器或发布网站。要从冻结分类和研究包重建数据，可依次运行 `node ontology/benchmarks/assemble.mjs`、`node ontology/benchmarks/record-audit.mjs`，再运行格式工具和验收。前者先产生未审计状态；后者只允许已经实际审阅过的精确输入哈希。更改标题、来源或归属后，必须进行相应新审阅，不得修改哈希来自动取得PASS。

稳定ID不得因标题、顺序、内容哈希改变而重新编号。一个规范节点的多处展示仍然只计一次。父边是编辑导航和主题联系，不表示数学蕴含或先修关系；不要让未来图算法把它升级为证明依赖。数学定义、定理正文和用户原笔记仍由原有内容管道负责，本目录不维护第二份证明。
